## 2. 测量校准：为什么不能直接缩放全部旧输出

Qwen3.5原生定位使用0–1000坐标，见[ms-swift文档](https://swift.readthedocs.io/en/v4.0/BestPractices/Qwen3_5-Best-Practice.html)。旧学生训练/评测提示要求原图像素；N/A1/A2主要仍输出原生坐标，而U已通过定位训练学会像素输出。对同一批旧输出一律缩放，会错误解释已经正确遵循像素提示的U。

| 旧最小循环模型 | 旧像素主分 | 将全部旧框固定解释为0–1000的事后诊断分 |
|---|---:|---:|
| N | 1% | 85% |
| A1 | 1% | 85% |
| A2 | 1% | 89% |
| U | 85% | 0% |

[诊断逐项汇总](9b-coordinate-diagnostic-results.json)和[解释](9b-coordinate-diagnostic-report.md)已归档；这两列不能逐题、逐模型取较高值，也不能将旧诊断当作新正式评测。

新增独立脚本`tools/evaluate_9b_native.py`，定位提示对**所有模型**明确要求输出0–1000坐标，再统一转换：`x_pixel=x_1000×原图宽/1000`，`y_pixel=y_1000×原图高/1000`，最后与原始像素标注计算IoU≥0.5。原模型文本不改写，归一化框和换算框分别保存；非法框拒绝解析，不按答案猜坐标系。其余三轴的提示、解析和计分不变。四项转换/边界/提示/其他轴保护测试已在本地与5090运行环境通过。

已固定[新版评测协议](9b-native-evaluation-protocol.json)，SHA256为`39013caa8884a7d98404f260cbe9d40ccaf9cdf4ad9070c4d7f381ac83877fb5`；[外部登记回执](9b-native-evaluation-registration.json)已服务端核对。原生定位提示CPU检查完成，最小/正式清单共800/16,900提示，其中100/2,400定位提示改变坐标契约；新定位prompt最大457/483 token，未超2,048上限。

这是用户在旧工程最小循环和部分正式训练之后要求的测量修订，不追溯声称训练前已登记。训练目标仍为原图像素；从像素训练提示到原生坐标评测提示的指令泛化也是解释因素。原ARP阶段C仍未放行，与7B同时改变学生、教师和测量契约，不能单独归因于容量。

1. `continue_9b_training_only.py`接续原15次训练，跳过已完成且核验过的任务。逐次检查真实优化器步数、两路CE、梯度、适配器导出与恢复状态。每次完成即归档，不运行旧像素正式评测。
2. 全部训练结束后，重新核对恢复状态与健康日志。新的完成状态不再腾挪；此前旧策略已归档腾挪的状态，按不可变清单下载到AutoDL并精确还原，只移除校验后的临时下载包。15份正式恢复状态均保留供终局核验。记录裁剪前梯度最大值/中位数和实际裁剪阈值1.0，不把“有限”偷换成“完全无梯度波动”。
3. N基线先生成100条新定位输出，使用明确原生坐标提示。源码与登记固定的工程检查为准确率≥75%、解析失败≤5/100，对应用户期望约80%的合理区间；不达标即停止检查转换，不调提示刷分、不挑题、不自动重试。
4. N通过后，三个最小循环适配器各补100定位输出；每模型其他700条未改变提示的输出按源SHA复用。新增400次推理、最多15分钟GPU活动预算，单独登记为用户要求的测量校准，不重复任何训练，也不冒充旧两小时工程预算的一部分。形成新的四轴分数与五项验收/坐标校准报告。
5. 校准通过才启动16模型正式评测。每模型16,900提示，N一次加15个适配器；不加载优化器、不保留梯度，每次新进程重载适配器。正式生成预算仍为270,400提示、40小时绝对评测上限；不根据分数追加任务。
6. 每模型完成后，立即核对16,900唯一ID、清单覆盖、原始输出重评分、四轴汇总；压缩直接上传[9B Release](https://github.com/Jerry-114514/Jerry-vibe-coding/releases/tag/arp-9b-122b-20261017)，核对服务端大小和SHA256。
