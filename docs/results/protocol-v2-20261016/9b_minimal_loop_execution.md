- [新执行器与预检输入逐张量一致性](9b-loop-cpu-input-equality.json)：四轴实际图片的全部处理器张量一致；没有做GPU反向或显存测量。

## 强制执行顺序

1. 7B全部16模型完整评测、既有分析和归档结束；9B已有完整显存预检队列。
2. 9B预检100次真实更新及独立压力测试完成，reserved≤28GB才准入。未准入或预检失败则最小循环不启动。
3. 控制器 `run_9b_minimal_when_ready.py` 已实际排队。通过准入后先评测N，再训练A1到50步退出，新进程恢复至100；A2/U各100。每臂均从原始9B权重初始化，不复用预检训练后的适配器。
4. 三个适配器各在独立评测进程重载，分别完成800提示四轴开发评测；N只有未训练基线，不创建适配器/优化器。
5. 独立核验五项：缓存/学生长度边界、双CE有限且梯度非零、适配器导出与恢复张量一致、完整四轴逐题重评分与汇总一致、实际新进程恢复50→100。保存首次恢复损失、CPU/CUDA/Python RNG恢复证据。

预检和最小循环共用已登记的2小时预算；最小循环额外最多90分钟，终点写入绝对UTC预算文件，重启不刷新额度。显存>30GB、磁盘<5GiB、非有限/零梯度、输入超限或哈希变化即停，不静默截断。

## 保存、记录与后续边界

`route_b_9b_loop.py` 支持A1/A2/U、五个既定seed和100/1,000步两种阶段，检查点每50步保存优化器、适配器和CPU/CUDA/Python RNG。损失、两路CE、梯度范数、步耗时及显存峰值逐步记录；评测只有推理，不加载优化器，所有参数关闭梯度，并单独报告生成长度触顶次数。

各臂原始适配器、检查点、逐题账本和验收报告直接上传9B Release，每臂单独归档以控制临时磁盘占用。本机只同步代码及小型证据。

**当前没有开始9B GPU训练，五项真实验收尚待运行。** 本控制器只排队最小循环，不自动调用15次正式训练。正式训练入口强制要求最小循环通过；正式评测入口强制要求全部15次1,000更新训练完成。后续仍需正式调度与存储/恢复验收，不能把执行器已实现当作正式实验已完成。
