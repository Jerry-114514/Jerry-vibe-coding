## 先做哪一个实验

**优先确认 Qwen3.5-9B 在新 seed 下，归一化定位训练目标是否仍优于像素目标。** 既有 2×2 对照的定位主效应在开发集为 +22.75 个百分点，在当时的保留子集为 +21.875 个百分点，两个校正区间都排除零。但只有两个训练 seed，P-D 复用了历史端点，且两种表示改变了数值文本和 token 长度。原 U-seed137 的 42.58% 分数继续保留；下一轮不通过重解释坐标改分。证据见[原对照报告](9b-repair-final/report/report.md)。

第一轮以 **P-G（像素、仅 GT 单 CE）和 N-G（归一化、仅 GT 单 CE）**为配对。两组都从同一冻结基础权重起跑，不继承已有 LoRA；固定同一 U 混合训练池、每 seed 数据顺序、步数和训练设置，仅转换定位标签表示。GT-only 让本轮不需要重调教师 API；它确认的是表示在 GT-only 条件下的效果，不检验教师交互，也不声称隔离了 token 长度效应。

- **预算与冻结**：8 个新 seed（2026111101 至 2026111108），每个 seed 两臂各 1,000 次真实更新，另评测一个零更新基础模型。随机化每对的运行先后，记录固定的调度顺序；保持样本、有效批量和更新数一致。复用原 9B repair 的 BF16 LoRA 参数，以训练锁为准。发布模型 revision、配置、数据、代码与输出契约的 SHA256 后才运行正式训练。
- **评测**：CPU 阶段先找一份此前未用于训练、校准、开发或旧保留子集的独立确认集，目标四轴各 120 原题。对历史角色和训练池做原题 ID、图片内容哈希及近重复检查；确认样本不足则在看到新结果前重新登记数据来源或缩小结论，不把旧保留集当作新盲测。所有模型固定同一推理提示、EOS 和计分口径：输出 0–1000 坐标，按原图尺寸转换，IoU≥0.5；保留原始输出、解析失败和长度截断，禁止按 GT 选择坐标单位。另做旧保留集小样本兼容性复核，与新确认结果分开。
- **主终点**：新确认集上 N-G−P-G 的定位准确率配对差。展示每 seed 差值、均值和区间；按训练 seed 作配对符号翻转检验（双侧，枚举 2⁸，解释依赖差值符号可交换假设），以 seed 和图像簇为抽样单位做区间敏感性分析。主检验单项、α=0.05；其余三轴作为次要终点单列 Holm 校正。方向为正且主检验通过才称为确认支持；未通过不宣称等效。同步报告基础模型差值，不根据结果追加 seed 或选择端点。
- **停止规则**：GPU 先执行 100 次真实更新、最长输入压力测试、断点恢复、适配器重载以及 N 基线小样本校准；无 OOM、无 NaN/Inf、步数和逐题账本对齐，输出协议与显存门槛均通过才放行。正式运行允许从同一状态恢复；无法恢复或条件性输出异常须登记失败，不得用挑选的 seed 补齐。归档每步损失、显存、耗时、输入锁、端点及逐题输出。
- **后续分支**：若要回答教师监督是否改变表示效应，再单独登记同 seed、同输入的 P-D/N-D 对照，可先用已有教师文本并核验覆盖。之后才做 7B 或另一模型族复现。原 ARP 阶段 C 仍未放行；若目标是回到原 ARP 主线，需另行解决同检查点精度桥接和有效性门槛。

依据：[9B 预检](9b-full-preflight-result.json)、[9B 评测记录](9b-v41-final/report-status-evidence.json)、[7B 4090 预检](p14_full_preflight.md)。GB 为十进制，GiB 为二进制；reserved 不含全部 CUDA/驱动开销，必须同时记录全卡峰值。32 GB 卡上建议预检全卡最低空闲不低于 4 GiB（含压力测试），PyTorch reserved 不高于 26 GiB；有并行进程、输入规格变化或预检不过线时，先排除并发并复验。若需原配置而 32 GB 实测不过，再选 40/48 GB；不把降精度、缩短输入或改 LoRA 范围当作原协议复现。若只恢复和重算既有统计，无需 GPU。

按历史 GT-only 16.7–21.9 分钟/千步，16 次更新阶段约 **4.5–5.9 GPU 小时**；17 个模型每个约 960 条提示，按历史 0.20–0.52 秒/条，生成约 **0.9–2.4 小时**。计入预检、加载、验收和保存，建议预留 **7–10 小时计费 GPU 时段**，不含可能较慢的下载和环境安装；以新卡预检重新估算。租金用下单时的元/小时乘计费时长。教师无需在本机加载，也不需要重付原缓存生成费用。
