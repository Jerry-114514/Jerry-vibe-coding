# 9B 定位续实验执行指南

2026-11-12（北京时间）｜状态为指导方案，正式协议与新确认集待冻结。

**现在不用租卡。** 先在本地完成数据与脚本验收。确认集通过历史曝光排查和人工盲审、运行协议冻结后，租 **一张 32 GB RTX 5090**，先跑同配置预检，再启动 16 次 9B BF16 LoRA 训练及顺序评测。当前优先回答定位结果能否复现，本轮教师 API 预算为零。原 ARP 阶段 C 仍未放行，本轮登记为独立的 9B 定位确认实验。

## 1. 要回答的问题

**在同一 Qwen3.5-9B 基础权重、同一混合训练池和统一归一化部署口径下，归一化训练契约能否稳定改善新图像的定位表现？**

旧 2×2 的 GT-only 在旧保留集上两个种子分别改善 **+20.83 和 +14.17 个百分点**，均值 **+17.50 个百分点**。这两次结果用于提出假设和估算精度。旧实验同时改变了提示、数值表示及 token 长度，且旧保留集曾经使用。新设计控制模板差异并引入新训练种子与新图像。旧 U-seed137 的 **42.58%** 留在原始结果中。[设计复审](experiment-design-review-20261111.md) · [旧 2×2 数据](9b-repair-final/report/report.md) · [数据流审计](dataflow-audit-20261111/audit-decision.md)

## 3. 数据与配对训练

### 确认集

- **先锁排除规则。** 沿用原题 ID、原图 SHA256、解码后 RGB 指纹及近重复图像簇，补查可核实的历史训练、校准、评测和 API 账本。旧保留集命中的 **480 道原题、425 个图像组件**整簇排除。选择题同时排查规范化题面加无序选项集。保留逐条来源、排除理由及已核对的曝光范围。
- **定位为唯一主要终点。** 建议先按 RefCOCO testA/testB、RefCOCO+ testA/testB 和 RefCOCOg test 各 **48** 道筹备，共 **240 道**，全轴每个近重复组件最多取一道。当前五个分层的候选各有 166、177、169、177、193 道；这个数量尚未经完整曝光补查及盲审。选样前固定抽样种子、匹配规则和每层备用顺序。让两位审阅者在隐藏模型输出与实验臂的条件下独立核对图像、指代表达、GT 框和歧义，按预先登记的规则处理分歧。盲审淘汰只从同层备用顺序补。若任一层未满、无法取得 240 个不同组件，或旧账本的精度预演显示不足，先修订来源或样本规模并重新登记，然后才冻结和租卡。240 是计划规模，统计把握度须用旧输出的配对错判率和 seed 差异情景估算。
- **其余三轴各 120 道原题。** POPE-style 三类各 40。AI2D 派生一致性每原题保留五个改写，五个都答对才计 1，统计按原题、按图像簇对齐。MMMU 为单图、公开 A–D 答案的推理代理，建议农业 2 道，会计与建筑工程各 5 道，其他 27 科各 4 道；同时给按题分数和学科宏平均。冻结前复核所有配额和来源，分别记录原题、提示行及独立图像簇数。[候选源行、配额与历史曝光证据](dataflow-audit-20261111/confirmation-candidates.md)

### 配对训练

| 条件 | 训练 | 定位目标 |
|---|---|---|
| P-G | GT-only，单 CE | 原图像素 xyxy |
| N-G | GT-only，单 CE | 原图坐标归一到 0–1000 的 xyxy |
| 基础模型 | 零更新，单独评测一次 | 分别按两种推理口径请求输出 |

- 8 枚新 seed，**2026111101–2026111108**，每个 seed 两臂各 **1,000 次实际优化器更新**。冻结一份等比例 U 池，配对内复用同一 LoRA 初始状态、图像、样本顺序和每轴剂量，更新计划保证每轴 250 步。记录逐步样本 ID、token 数、学习率、梯度、峰值及耗时。每对的先后顺序预先生成，8 对内平衡两臂先跑的次数。各模型从同一基础权重新建适配器。
- 复用已验证的 9B BF16 LoRA 主配置与最大序列长度；定位的两种提示使用对称模板，保持图像、文字问题和 JSON 结构一致，明确单位、边界、尺寸信息和统一的数值序列化精度。量化往返误差、提示/答案 token 分布和超限情况在 CPU 预验收时报告。非定位的输入与目标 token 必须逐项相同。主对照估计训练坐标契约的整体效果。
- 正式训练只取第 1,000 步端点。同一运行可用校验通过的优化器、调度器、RNG、样本游标及日志恢复。禁止结果触发追加步数、补新 seed 或选择中途检查点。不可恢复的端点和原因保留在账本；若少于 8 个完整配对，主确认标记为未完成，剩余配对只作描述。

## 4. 评测与论文判据

所有 17 个端点用相同归一化部署口径跑四轴；定位另外交叉跑原图像素提示。归一化预测按原图宽高反算，像素预测按原图像素解析，两者用同一 GT 和 **IoU ≥ 0.5**。固定图像处理、禁用 thinking、确定性生成、上限 128 个新 token，核对 EOS 为 `[248046, 248044]`。解析器按提示分配，越界、非有限值、非正面积框、格式错误或达到长度上限且未见终止符均计错；缺行属于运行故障，应从逐题账本恢复并补齐。保留原始文本、生成 token、终止原因及评分状态，禁止根据 GT 反推坐标单位。每个端点顺序推理，不加载优化器、不保留梯度。

- **主比较**：归一化部署口径下 N-G−P-G 的定位准确率差，单位为百分点。报告 8 个配对差及均值；双侧精确配对符号翻转枚举 2⁸ 个配置，训练 seed 是独立重复。检验解释依赖零假设下配对差的符号可交换性。95% 区间按 seed 与定位图像簇配对重采样，在五个来源分层内抽图，报告两类不确定性。
- **预登记实用阈值建议为 +5 个百分点。** 方向为正、主检验 p < 0.05 且点估计至少 +5 pp，才称结果支持有实用意义的方向；只有区间下界也达到 +5 pp，才表述为证据支持至少 +5 pp。区间不确定时保留数据和效应范围，避免等效表述。基础模型差值单列作解释，若要声称恢复至基础水平，须先设计并注册非劣效比较。
- **机制与次要结果**：像素交叉评测报告训练契约 × 推理契约差值、解析率、截断率和逐题 IoU 分布；单列两种口径与五个定位来源。三条其他轴的 N-G−P-G 用 Holm 校正。若收益主要在归一化提示下出现，论文归因限定在训练与部署格式适配；若两种推理口径同向，则作为跨格式泛化证据。教师增量、不同模型族泛化和原 ARP 门槛分别留待独立实验。

## 5. 何时租卡，以及租多久

**本机实测。** RTX 5070 Laptop 由 `nvidia-smi` 识别，总显存 **12,231 MiB（11.94 GiB）**。本轮只检查了驱动与显存，当前所用 Python 未找到 PyTorch。可先用 CPU 跑数据和解析测试；如需真实本地推理，再安装独立 CUDA 环境并用现成小模型做小批量冒烟。历史 9B BF16 评测的 PyTorch reserved 达 **18.895 GiB**；本机量化或卸载输出若用于调试，应单独标记精度与后端。

| 用途 | 已有测量 | 决策 |
|---|---:|---|
| 9B 完整预检含压力测试 | **22.750 GB / 21.188 GiB** reserved | 32 GB 5090，单卡 |
| 9B 旧 GT-only 两臂正式训练 | **20.525–21.250 GB** reserved | 同卡同流程；新模板仍需预检 |
| 9B 旧 BF16 逐模型推理 | 最高 **20.288 GB / 18.895 GiB** reserved | 顺序评测沿用同卡；24 GB 仅在同配置实测通过时可作评测备选 |

reserved 是 PyTorch 显存池统计。正式预检同时采集全卡显存。两臂各用独立工程 seed 在开发数据上跑 100 次真实更新，包含最长训练样本压力测试、一次中途退出并从断点继续，以及适配器重载评测。放行要求为步数与游标完全对齐，损失和梯度有限且梯度非零，两种解析器通过同一几何框的坐标往返夹具，旧归一化提示在开发夹具上能重放既有基线，且无 OOM，reserved ≤26 GiB 且压力测试全卡最低空闲 ≥4 GiB。两臂都通过才启动正式训练。32 GB 不通过时先核对环境、并发和冻结配置；原配置确认仍超限才考虑 40/48 GB。设备与历史实测见 [NVIDIA 规格](https://www.nvidia.com/en-us/geforce/graphics-cards/50-series/rtx-5090/) · [完整预检](9b-full-preflight-result.json) · [正式评测资源记录](9b-v41-final/report-status-evidence.json)。

| 项目 | 单卡估算 |
|---|---:|
| 16 次训练的更新阶段，历史每千步约 16.7–21.9 分钟 | **4.5–5.9 小时** |
