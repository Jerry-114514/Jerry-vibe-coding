# 7B定位测量审计与补救方案

2026-10-17。原7B训练与原计分产物仍保留；这里修订其定位能力解释，不覆盖原始输出。当前新增审计属于结果出现后的测量诊断，不能追溯声称事前登记。

## 已有实证

[全16模型、每模型2400条的CPU审计](7b-grounding-cpu-audit.json)已完成，[逐模型报告](7b-grounding-cpu-report.md)与逐题证据在Release。2400条定位题的处理器网格尺寸均不同于原图。对同一批旧输出，分别固定三种坐标解释，结果如下；三训练臂为五seed均值。

| 模型/臂 | 原图像素：原报告 | 处理器像素换回原图：诊断 | 固定0–1000：诊断 |
|---|---:|---:|---:|
| N | 67.792% | 85.500% | 0.083% |
| A1 | 66.133% | 83.742% | 0.025% |
| A2 | 67.458% | 85.375% | 0.017% |
| U | 77.658% | 73.558% | 0.058% |

N的原图像素解析失败498/2400，处理器像素解析失败10/2400。这支持原图/处理器像素尺度混杂，而不支持7B默认输出千分比。Qwen官方[模型介绍](https://qwenlm.github.io/blog/qwen2.5-vl/)说明Qwen2.5-VL使用绝对坐标；不能直接套用Qwen3.5的原生坐标惯例。

U−N在原口径为+9.867个百分点，在统一处理器像素诊断下为−11.942个百分点。**两者都不能通过挑较高分变成“修正主分”**：旧提示要求原图像素，U可能更遵循旧指令，而N更多遵循预训练的图像尺度。这里表明结论强烈依赖坐标契约，不能把原增益直接解释为定位能力增长，也不能仅凭诊断断言U损害了定位能力。

## 建议的补救顺序

1. **先完成无GPU的证据审计。** 固定并保存每题原图宽高、处理器实际网格与patch大小、旧原始框、三种诊断分、解析失败和来源SHA；禁止按GT或臂选择单位。此项已完成。
2. **原生尺度复测是首选主修正。** 对16模型使用同一明确的“处理器缩放后像素”提示，告诉实际宽高，再统一换回原图计算IoU。只需2400×16=38400次生成，不重训，不重跑其他三轴。该方案更贴合7B原生尺度，可减少额外格式转换负担；应在新生成前另行冻结，而非拿旧输出最高诊断分替代。
3. **共同0–1000提示作为格式敏感性对照。** [已冻结的独立审计](7b-grounding-audit-protocol.json)排队了38400次明确千分比提示生成，等待9B当前队列和交付完成后使用GPU，避免抢占其夜间主队列。它衡量坐标指令敏感性，不能称为7B原生口径。旧定位时延外推纯生成约6.47小时、约17.47元；新提示可能改变长度，另有装载/校验/上传开销，固定新审计GPU墙钟上限12小时。
4. **分开报告格式遵循与定位。** 主指标仍对全部题计算准确率；同时报告合法框比例、格式失败、越界和IoU分布。只在有效框上计算的条件IoU有选择偏差，只作解释，不能替换全量主分。三组定位差值给五seed配对图像簇区间，新增单轴族按3项校正；原12项比较族保持原样，不混称一次预注册检验。
5. **保留其他三轴，暂停跨轴能力推断。** 其他三轴不因坐标错误自动作废。四轴宏均值、grounding进入的G_floor和跨版本阶梯暂标测量敏感；可另报三轴敏感性汇总，但不删掉不利轴后改称主结果。统一测量完成后再重算派生指标，标明其协议。
6. **追加训练要有明确触发。** 先核对训练/评测图像哈希重叠、教师答案尺度、实际token暴露与更新预算。若新固定契约下U仍仅在训练过的输出格式占优，再考虑独立的格式/数值转换控制臂；该臂不应被叫作“纯格式”因果控制，因为它也可能学到数值先验。不先重跑全部15次训练，不按显著性临时追加seed。

## 可以保留和不能宣称的内容

教师缓存、双CE训练、15次真实更新、适配器保存与恢复、其他三轴测量和完整交付仍是可复核的工程与探索性结果。原像素提示下的旧分数仍是该端到端指令任务的结果，但**尚不支持将U的grounding增益归因于纯空间定位能力**。7B的定位发现也不能用于放行原ARP阶段C。

原始报告与统计不删除；[7B原报告](7B独立自蒸馏实验结果报告.md)增加本审计说明。所有新增测量需单列协议、时间、SHA、输出与校正族，不冒充原实验事前设计。
