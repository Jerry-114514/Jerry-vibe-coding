# 补实验执行修订与已实施改进

本文件承接《ARP_整体改进与补实验方案_20261016.md》，记录基于真实运行发现的执行改进。全方案尚未完成；新正式训练仍受目标家族 C 判定和测量验收约束。

## 1. 数据隔离先于扩大调用和训练

公开 AI2D、MMMU 的 34 个源 Parquet 共 3,397,133,636 字节已完成官方 revision 与 LFS SHA256 核验。候选索引保留了多图、开放题以及最多 9 个选项；定位使用新的 REFER test 表达，存在性题由原 REFER 保存的 COCO 标注子集构造，单列为 POPE-style，不能冒称原官方 POPE。

初版候选划分发现 245 对近重复候选，其中 207 对涉及跨用途或历史图片。仅靠字节/RGB 完全相等去重不足以处理这一问题。现已实施保守图像图：

1. 多图题包含的图片属于同一连通组。
2. 对全部历史与新候选图像计算 dHash，汉明距离不超过 4 的图像全部连边；共有 4,464 条边，包括历史图像之间的边。
3. 候选组只要连到历史训练或评测图片，整组从新审计/确认候选中排除。共排除 798 个候选原题单元，数量不是图片数。
4. 按完整连通组分配用途，再以确定性配额修复满足预定分层数量，供体用途的最低配额保持不变；不使用模型预测或分数。

这是保守的自动隔离规则，可能合并不相同的图像、改变候选组成；它不等同于人工确认了视觉重复，也不能保证识别任意裁剪或语义改写。原始候选版本保留用于解释数据处理差异。

## 2. 保留样本量，明确开发数据来源

保守过滤后 AI2D test 剩余 2,506 个候选题，不足以同时提供 120 个新校准题和各 1,200 个审计/确认题。严格分配的 v3 因配额不足停止，保留失败记录。

v4 的处理是将一致性校准改用 120 个明确标记的历史 MMBench 开发原题；新 AI2D 用于审计/确认。历史开发题只用于协议校准，不能当作新独立证据。新的审计/确认图像图仍排除了所有历史连通组。其余三轴校准保持新来源。最终冻结规模如下：

| 用途 | 每轴原题单元 | 总原题单元 | 提示行数 |
|---|---:|---:|---:|
| 校准 | 120 | 480 | 960 |
| 审计 | 1,200 | 4,800 | 9,600 |
| 确认候选 | 1,200 | 4,800 | 9,600 |
| 历史已批准训练代理 | 各轴数量不同 | 2,149 | 3,545 |

一致性五改写始终作为一个评分和重采样单元。审计一致性包含 331 个图像连通组，确认包含 315 个，因此 1,200 个题目不等于 1,200 个独立图像，也不构成功效保证。后续区间必须按图像组处理相关性。训练代理沿用已批准的原独立来源，新 test 题没有加入训练。

## 3. 多图预算按实际处理器验收

已实现 Qwen 3B/7B 全 BF16 的有序多图后端：保留 1–7 张图片并编号，单次输入总视觉 token 上限 1,280，输出上限 128，贪婪解码，非有限 logits 立即停止。

真实 CPU 预检发现两处依赖行为：`size` 默认值会覆盖单独传入的 min/max pixels；当小图缩放的最小和最大面积相同时，补丁网格向上取整还可能越过上限。现改为显式传入 `size`，并在每图最小/最大面积之间留出取整区间，然后核验实际 `image_grid_thw`。

旧 `clean-inputs-v4` 的单图部分输出保留为停止记录，不能拼接到修复后结果。新 `clean-inputs-v5` 从头运行两个模型各 960 条校准提示。全部多图/开放校准案例及七图边界已通过实际处理器检查；多图案例包含 2、4、5 张图，七图边界实际为 1,155 个视觉 token。CPU 输入检查不能替代模型生成、评分或显存验收。

评分支持真实选项范围，禁止将九选项题裁成 A–D；开放题使用按内容 SHA256 锁定的 MMMU 官方解析和评分代码，保留 Apache-2.0 许可证。定位原图像素协议和 API 的归一化协议分别命名，不按答案或输出大小猜单位。

## 4. 大教师与 API 的真实边界

阿里云工作空间接口已连接并实际完成 164 次补实验调用。`qwen3-vl-plus` 可用于单独登记的商业 API 教师开发实验；它实测返回 top-5 概率，不能直接替代原 top-50 加尾部桶 KL。

精确访问测试中，`qwen2.5-vl-32b-instruct` 返回 HTTP 403 `access_denied`；固定日期的 `qwen3-vl-plus-2025-12-19` 返回 HTTP 404 `model_not_found`。不能把可调用的商业别名当作已验证的 32B/72B 检查点，也尚未确认该别名不可变。

已有主机 cgroup 内存上限为 128,849,018,880 字节，但系统盘与数据盘剩余空间当时分别约 7.18GB、18.07GB。官方 InternVL3-14B 未量化权重实际 30,234,629,208 字节，Qwen2.5-VL-32B 实际 68,283,251,376 字节。仅主机内存充足不能解决显存和持久存储问题。14B 需要在现有节点完成后安排可再下载权重的缓存周转及 CPU 卸载预检；32B 还需要可用模型权限、其他精确接口或另行验证的流式加载方案。

## 5. 数据已交付到 GitHub

阶段 [Release](https://github.com/Jerry-114514/Jerry-vibe-coding/releases/tag/arp-protocol-v2-20261016) 已保存数据源版本、候选索引、原始划分、保守 v4 清单、排除证据和阶段结果。

此外，冻结清单引用的 5,704 张实际输入图片，共 1,398,152,841 字节，已由 AutoDL 直接打包上传。资产前缀为 `arp-protocol-v2-20261016-20261016T092731Z`，包含 inventory 和两个 `.tar.gz.part000/001` 分片；均已核验服务端大小与 SHA256。解压后把 `input-tree/` 的内容恢复到仓库根目录即可复原原图路径；历史训练图像和教师缓存仍在原正式实验 Release。

本机只同步代码和小型摘要，原始图片、Parquet、模型和训练状态留在 AutoDL/GitHub。密钥不写入仓库。每个校准模型完成后自动重评分、核对题目覆盖和输入图片数量，再上传账本及显存记录。

## 6. 后续顺序和仍未完成项

先完成 v5 两模型校准及测量验收，准备双人定位盲审材料、冻结审计协议和新 floor 答题器，再运行新审计与配对 C 判定。保守自动隔离不会被标记为已完成人工盲审。

只有目标家族满足新 C 的严格反转、配对噪声和有效域要求，且训练规则确实选择不同轴时，才进入配对多 seed 的 D；否则保留负结果，明确记录正式训练未放行。新确认集在此前保持不参与调参和选轴。

后台监控每五分钟检查真实 PID、状态、日志进度、GPU 和备份回执。原数据划分失败若已由完成的新版本替代，会保留历史原因并避免重复报成未解决故障。该监控记录远程日志，不等于独立的聊天通知服务。

## 7. API 教师替换与更大模型候选

按用户最新要求，当前 API 教师统一使用已验证可调用的 `qwen3-vl-plus`，不再等待精确 32B 权限；历史访问失败记录保留。代码从统一配置读取模型，禁止旧冻结实验混入新模型。新增合成图的颜色、JSON 与归一化定位验收，当前教师通过。另有 397B、122B、35B 候选已完成实际访问探测，但需单独校准其输出契约，详见 [大参数 API 教师筛选](results/protocol-v2-20261016/large_api_teachers.md)。
