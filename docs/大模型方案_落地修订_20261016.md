## 有证据支持的技术修订

1. 397B 已能在用户现有 DashScope 工作空间直接调用，不需要额外供应商。
2. qwen-vl-plus/max 的名字不能证明其参数量或 Dense 架构；-latest 不能当作固定快照。实际不可调用时保留失败，不自动替换同名或近似模型。
3. API 定位显式指定 [0,1000] 坐标，固定映射回原图，使用已存在的显式 JSON 解析器，允许其预先支持的 singleton bbox_2d 包装和代码围栏。不同坐标契约分开登记，不按输出大小猜单位。
4. 本地 Qwen2.5 定位使用处理器实际网格的像素坐标，固定映射回原图。120 条开发定位校准中，3B/7B 均零解析失败，正确率分别 78.33%/83.33%。这些是开发结果。
5. “DashScope 不返回 logprobs”过于绝对：122B 的合成图调用实测返回 top-5。主线仍按用户方案做序列 CE；未验证 top-50，不能替代原 KL。
6. 参数数量和激活参数不直接证明教师更强；以相同校准题和后续蒸馏结果判断。API 费用按实际 usage 记录，文档中的价格和总工期仅作待复核估算。
7. 0.5 GT-CE + 0.5 teacher-CE 是主线目标损失设计，尚未实现并验收该正式训练配置；现有 7B 的 100 步工程预检不能冒充新协议正式训练。
8. 旧 P0 配对 C 重算未放行，保留负结果；新增审计有独立版本。只有新 C 判定和选轴条件实际满足，才运行 D 多 seed 训练。人工盲审未完成时不标记完成。
