# ARP 整体实验改进与补实验方案

> 日期：2026-10-16
>
> 状态：待执行的研究协议草案；本文不包含尚未运行的补实验结果。
>

>

## 1. 核心建议

现有实验已经完成完整运行、逐题重评分、权重与优化器状态核验，并完成 GitHub 备份。这证明产物齐全、计算可以复现；它不能替代对“研究标准卡中的定义是否被正确实现、统计比较是否公平”的审查。

结合现有成果，下一轮应优先解决四件事：

1. 对齐原文公式与代码，重算 C、D。当前发现相对掉分分母、训练净增益定义及训练臂共同有效样本集需要复核，优先使用已有账本完成 CPU 补分析。
2. 区分量尺引起的严格排序反转、平局和接口失败。当前 Qwen 的部分不稳定性可能来自两点阶梯的 headroom 退化，InternVL 的定位结果又受到极高解析失败率影响。
3. 将选轴数据与最终确认数据分开，增加配对随机种子和训练臂差值区间。A1 对 A2 的原始优势仅为四轴之和的 0.317 个百分点，当前不能宣布稳定胜出。
4. 优先增加 Qwen 32B、InternVL3 14B，并将推荐训练配置扩展到 7B 学生、32B 教师。38B、72B 放在增强方案中，避免大模型成本掩盖基础定义问题。

**保留原实验全部结果，作为 v1 探索性基线。新公式、新解析协议、新数据和新模型分别编号；不覆盖旧账本，也不把重分析包装成独立复现。**

| 训练臂 | POPE | 定位 | 一致性 | MMStar | 四轴增益之和 |
|---|---:|---:|---:|---:|---:|

| A2：一致性训练 | +0.022 | +0.250 | +0.375 | +2.067 | +2.714 |

| N：不更新 | 0 | 0 | 0 | 0 | 0 |

需要直接检验的现象：

- A1 比 A2 仅高 **0.317 个百分点的四轴之和**，换成四轴平均变化仅约 0.079 个百分点；没有差值置信区间和多种子，不能认定优势可靠。

- 仅按现有九个类代表设置的严格点估计最大值计数，A1 排第一 4 类、A2 排第一 4 类、U 排第一 1 类。这未应用显著性或并列阈值，也不能把九个类当成九次独立重复实验。

### 2.3 C 的 go 需要重新解释边界

| 家族 | 旧实现经验等价类数 | F_scale | 95% CI | F_noise 的 95% CI |
|---|---:|---:|---|---|
| Qwen | 9 | 0.0833 | 0.0741-0.1944 | 0-0.3302 |
| InternVL | 54 | 0.5123 | 0.4012-0.5957 | 0-0 |
| LLaVA | 10 | 0.3167 | 0.3167-0.5667 | 0-0 |

旧协议的总体 go 来自 InternVL、LLaVA 的分离结果，不能将其当作“Qwen 内选轴已经有强证据”的证明。有限次重采样得到零噪声翻转，也不等于总体噪声严格为零。

另外，floor correction 主导翻转的原预测没有获得支持；Qwen 的同质 floor 对照既没有改变选臂排序，也没有消除其旧 F_scale。后续必须保留这两项结果，不能以扩模型为理由删去负面证据。

## 3. P0：先做定义对齐与已有数据补分析

这一部分主要使用已有原始生成、评分账本和训练后账本。原则上不需要重新下载大模型；仅改变解析器时优先对旧原始生成做 CPU 重评分并保留旧版。改变提示、输入处理或精度，才需要相应的新推理。

### 3.1 对齐“相对掉分”的分母

研究标准卡第 2 页的零分母护栏以校正前的 `x_L=0`、校正后的 `x_L=c_a` 为条件；这对应以大模型分数为分母的相对下降。当前 [analyze_rulers.py](https://github.com/Jerry-114514/Jerry-vibe-coding/blob/codex/arp-autodl/tools/analyze_rulers.py) 使用的是 `small` 或 `small-floor`。

应逐式确认并在新协议中固定：

```text
绝对差：               x_L - x_s
底线校正后的绝对差：   (x_L - x_s) / (1 - c_a)
大模型基准的相对差：   (x_L - x_s) / x_L
对应底线校正相对差：   (x_L - x_s) / (x_L - c_a)
headroom：            (x_L - x_s) / (u_a - x_s)
```

例如 `x_s=0.4, x_L=0.8, c_a=0.2`，大模型基准的相对差为 `0.5`，校正后为 `2/3`；现代码的小模型基准分别得到 `1` 和 `2`，两种定义不能混称为同一个量。

验收要求：

- 形成“标准卡公式-代码公式-护栏-解析式测试”的逐项对照。
- 推荐主分析按标准卡大模型分母实现；保留小模型分母作为明确命名的敏感性设置。
- 测试零分母、sub-floor、负变化、headroom 分母符号、floor 因子抵消等情况。
- 分别报告修正前后的类数、pi、F、go/no-go、选臂与训练臂排名。
- 如发现标准卡自身有歧义，先在新协议中消除歧义，不把当前结果追认为已经验证了某个未明确的公式。

### 3.2 将严格反转与平局分开

对于只有两个端点的阶梯，若 `u_a=x_L`：

```text
(x_L - x_s) / (u_a - x_s) = 1
```

在所有轴通过定义域护栏、且分母均非零时，各轴会自然全平局。这是定义造成的退化，不是模型能力突然相同。当前 fractional tie credit 又会降低 `max(pi)`：如果九个类中八个唯一支持同一轴，一个类四轴全平局，就会得到 `1-(8+1/4)/9=0.08333`。这个数值与现有 Qwen F_scale 相同，因此必须逐类核实来源，不能直接把它描述为严格翻转。

新增并列报告：

1. 原定义 F，供与 v1 对照。
2. 不同量尺间“唯一最大轴不同”的严格反转比例。
3. 全平局率、部分并列率、无有效轴比例。
4. 稳定轴交集、有效轴数、各轴有效题目覆盖率。
5. 对保留 headroom 退化类和将其标为不提供排序信息两种处理的敏感性结果。

并列阈值建议预先固定主值 0.01，并完整展示 `0、0.005、0.01、0.02` 的敏感性分析。不同单位的量尺是否适合共用同一个绝对阈值，也应解释；不能选出最有利阈值后只报告该值。

### 3.3 重新定义 D 的主要净增益

标准卡第 4 页式(5)是校正分数的 signed difference：

```text
G_raw(arm) = Σ_a [x_post,a - x_pre,a]
G_floor(arm) = Σ_a [(x_post,a - x_pre,a) / (1 - c_a)]
```

当前 [export_results.py](https://github.com/Jerry-114514/Jerry-vibe-coding/blob/codex/arp-autodl/tools/export_results.py) 把 `[pre, post]` 当成新的缩放阶梯调用 `ruler_vector`，还包含相对分母和教师 headroom。应审查这些量是否仍是标准卡式(5)；原始增益与这一类归一化增益需要分表报告。

建议：

- 主要训练收益终点采用标准卡的 `G_floor`，同时完整报告 `G_raw` 和逐轴 signed components。
- 四轴平均增益可以附报，明确它是四轴之和除以四。
- headroom、relative 形式只作为预注册的量尺敏感性终点，不与主终点混用。
- 用于选轴的量尺定义和用于评价训练收益的效用函数分别写清楚，避免在不同归一化分母间悄悄改变研究问题。
- 重新计算并验证 N 的所有增益严格为零。

新确认集改变数据来源后，不能复用旧 MMBench/MMStar 的 `c_a`。预先冻结退化答题器及其随机种子，再在每个确认集上按相同评分单位、解析规则和共同样本域重新估计 floor；多图、不同选项数量与开放题分别明确计分。确认集的 floor 仅进入预先固定的收益终点，不反馈选轴或调参。主终点预先固定四轴等权、有效域与异常处理；post 低于 floor 或出现负迁移时仍保留 signed 分量，不能临时删轴。若主终点本身的定义域检查失败，应报告不可判定，并另列预注册的敏感性结果。

C 的 `c_a/u_a` 来自审计集和预先声明的锚点；D 的主收益终点使用确认集 `c_a`。若附报教师 headroom，教师身份须提前固定，并在同一确认集、同一有效域上重评分取得 `u_a`，不得直接混用审计分布上的数值。该敏感性结果与主终点分开报告。

### 3.4 给所有训练臂使用共同题目集和共同量尺集合

当前 D 的 `exclude` 对每个臂分别取有效交集，可能导致不同训练臂在不同题目群上比较。当前导出又只使用 B 上折叠后的类代表设置；B 上恰好同值的设置，在训练后可能不再等价。

改进方法：

1. 枚举全部 120 个原始设置，不直接丢弃 B 上经验重复设置。
2. 主分析保持 `parse_fail=wrong`，所有训练臂使用同一冻结完整确认集。
3. `exclude` 敏感性分析使用 base、teacher 以及 A1、A2、U 所有 seed 的共同有效原题/原图交集；同一配置固定一个比较域，报告交集大小、分层分布及被排除题目的特征。若跨配置直接比较，同样另报跨配置共同域。
4. 主商集优先依据代数函数及其定义域固定；经验同值折叠作为附加描述。
5. 若报告训练后的经验商集，按所有臂联合输出定义共同商集，避免各臂各自折叠后使用不同权重。
6. 不能将量尺类当成独立随机样本进行显著性检验。

### 3.5 排查 headroom 的小分母放大

现有 Qwen POPE 分数约为 `0.87478 → 0.87678`，差值仅 `0.002`。以该差值作训练收益的 headroom 分母，会显著放大很小的变化。U 在某个 headroom 类中排第一，尤其需要给出分母诊断。

保留原始 signed 结果，同时记录每个分母、其抽样区间、零分母/符号护栏触发率。新增“分母区间跨零”和预先固定的小分母阈值敏感性分析；不得通过截断或丢弃不利结果来改善主结论。

**P0 产物：** `formula_audit.md`、`analysis_v1_vs_v2.csv`、`tie_and_guard_report.csv`、`arm_common_support.csv`、完整 120 设置的训练臂增益表，以及所有变化的原因记录。

## 4. A 阶段改进：数据、定位协议与独立确认集

### 4.1 将数据用途分成四类

| 数据用途 | 可做的事情 | 禁止的复用 |
|---|---|---|
| 训练集 | 生成教师目标、训练 LoRA | 不进入审计与确认评分 |
| 开发校准集 | 检查模板、坐标契约、数值稳定性、确定公共超参 | 不作为最终收益证明 |
| 审计选轴集 | 计算量尺、pi、gate，固定 A1/A2 | 不用于选择最有利最终结论 |
| 独立确认集 | 锁定全部方案后统一评估所有臂和 seed | 不反过来调提示、选轴或选超参 |

已有评测题已经被查看并用于选轴，因此现在再把旧题随机切出一部分，不能称为从未使用过的确认集。旧数据用于探索和桥接；确认性主张需要新增独立数据。训练/评测没有图片重叠，也不能自动消除“选轴与效果确认共用数据”的选择偏差。[模型选择偏差研究](https://jmlr.org/papers/v11/cawley10a.html)

### 4.2 建议的新确认数据

| 轴 | 保留的旧基准 | 新确认来源建议 | 必须说明的边界 |
|---|---|---|---|
| 幻觉/物体存在性 | 原 POPE 三子集 | 未参与旧实验的 COCO 图像，按原规则构造 POPE-style 三种负例 | 新构造集不能冒称为原官方 POPE 分数 |
| 定位 | 原 RefCOCO/+/g val | 未参与旧实验、且与训练图像分离的 testA/testB/test 表达 | 同图多表达聚类；需检查不同 RefCOCO 系列共享图像 |
| 一致性 | 原 MMBench 五改写 | AI2D 等有标签多选集上的独立原题及五种语义等价模板 | 变更数据来源要单列；五改写只算一个原题单元 |
| 视觉推理 | 原 MMStar 全集 | MMMU 独立确认集，优先使用当前已公开标签的 test 候选 | 新终点称 MMMU/视觉推理，不称“新增 MMStar 题” |

MMMU 官方目前提供 900 条 validation 和 10,500 条 test，且 test 答案已公开，可用于新确认设计；须固定数据 revision，并处理题目中的多图、选项数量和题型，不能强行套用原先单图 A-D 解析器。[MMMU 官方数据卡](https://huggingface.co/datasets/MMMU/MMMU)

AI2D 来源应追溯至 [作者仓库](https://github.com/allenai/dqa-net)；若使用现成转换版本，固定转换版本并核对原始 ID、答案与图像。不要假定下载到的 test 转换包同时包含可用于训练的 split。

每条轴目标至少 1,200 个原题评分单元；800 是最低候选规模，不是独立图像数或统计功效保证。先按旧数据的臂间 discordance 做功效模拟，再冻结样本量。若独立图像或标签不足，报告实际可用规模并调整精度目标，不用重复题或改写凑数。

### 4.3 优先修复定位测量的可解释性

现有 2,400 条定位题中，解析失败数分别为：

| 模型 | 解析失败 | 比例 |
|---|---:|---:|
| Qwen 3B | 497 | 20.7% |
| Qwen 7B | 501 | 20.9% |
| InternVL 1B | 2,226 | 92.8% |
| InternVL 2B | 2,285 | 95.2% |
| InternVL 8B | 2,398 | 99.9% |
| LLaVA 0.5B | 762 | 31.8% |
| LLaVA 7B | 0 | 0% |

LLaVA 7B 虽可解析，旧定位得分仍为零，说明“能解析”不等于坐标单位或定位语义正确。

具体补实验：

- 每模型分层抽取约 200 条原始输出，由两名标注者盲审，区分格式错误、坐标单位错误、图像缩放映射错误、有效但定位错误和截断；记录分歧与裁决。
- 保留旧严格协议：同一语义指令，要求原图像素坐标，按原解析规则评分。
- 另建原生输出协议：仅在独立校准集上冻结各家族明确的输出格式和坐标契约，再统一映射到原图坐标。转换由预先声明的单位、图像尺寸和处理器变换决定，不能看答案或根据框数值大小临时猜单位。
- 分别报告指令遵循率、可解析率、无条件定位正确率及条件 IoU；条件分数不得替代全题集主结果。
- 运行有/无定位轴的敏感性分析。如果去掉明显失效的定位测量后分离消失，应将结论收窄为接口或测量约定敏感性。
- 不根据确认集得分反复更换模板；校准失败的模型保留失败记录，并限制其语义能力结论。

### 4.4 去重与数据来源

延续字节和解码 RGB SHA256，增加原始 image ID、来源页面/题目 ID、感知哈希与近重复候选人工复核。同图的多个问题、不同裁剪以及五种一致性改写归入同一来源簇。新数据必须同时避开旧训练、旧评测、新开发和新确认的交叉重叠。

这只能检查本项目可见的数据，不宣称已经排除模型预训练中的 benchmark 污染。

## 5. B 阶段改进：更大模型与可比较阶梯

### 5.1 推荐模型矩阵

| 优先级 | 新模型/阶梯 | 实验目的 | 必须控制的混杂 |
|---|---|---|---|
| 主线 | Qwen2.5-VL：3B、7B、32B | 把两点补为三点；32B 可作更强教师 | 32B 官方说明额外使用 RL，不能解释为纯参数因果效应 |
| 主线 | InternVL3：2B、8B、14B | 相同三节点、两条边；检验较少视觉塔变化时的审计现象 | 保留 1B 的旧结果作共同子阶梯分析，不强行混成四节点主分析 |
| 增强 | LLaVA-OneVision：0.5B、7B、72B | 第三个同代家族的三点复现 | 72B 成本高，需固定其准确训练阶段与检查点 |
| 敏感性 | InternVL3 38B | 更强视觉塔/语言模型联合扩展 | 38B 改用 InternViT-6B，不和 14B 的 InternViT-300M 混称纯规模变化 |
| 可选 | Qwen2.5-VL 72B | 核验 32B 特有后训练影响与更大 ceiling | 作为额外检查点，仍非严格控制变量的参数缩放实验 |

官方依据：[Qwen 32B 模型卡](https://huggingface.co/Qwen/Qwen2.5-VL-32B-Instruct)、[32B 后训练说明](https://qwenlm.github.io/blog/qwen2.5-vl-32b/)、[InternVL3 家族结构表](https://huggingface.co/OpenGVLab/InternVL3-14B#internvl3-family)、[LLaVA-OneVision 72B](https://huggingface.co/llava-hf/llava-onevision-qwen2-72b-ov-hf)。

推荐措辞是“已发布模型的检查点阶梯”，而不是“只改变参数量的严格缩放定律”。

### 5.2 不把阶梯长度变化误认为模型效应

旧 Qwen/LLaVA 只有一条边，OWA 的 rho 实际不起作用；三节点才有两条边。

新主分析固定为三节点、两条边，继续使用 `[rho, 1-rho]`。同时报告原共同子阶梯、新三点阶梯及固定 ceiling 的敏感性分析。当前代码的 OWA 权重只处理一条或两条边；若直接加入四节点，必须先定义三条及更多边的权重规则并更新测试，不能只在配置中多填一个模型。

加入大模型也会改变家族 ceiling `u_a`。旧子阶梯在旧 ceiling、新 ceiling 下的变化需单独报告，避免把锚点变化当作能力规模效应。主分析的 ceiling 来自预先声明的具体检查点及审计集，不能逐轴挑选最有利模型。

### 5.3 精度与输入预算

- 新协议主线优先使用 BF16，并在原 3B/7B 上用独立校准集建立与旧“FP16 语言 + FP32 Qwen 视觉”的桥接。统一记录语言、视觉、logits、累积的实际 dtype。
- 旧账本不能直接与新精度结果拼成一个未标注的阶梯；是否复用需先证明计算协议一致，否则重跑相应新主分析节点。
- 冻结原生处理器、图像分辨率/patch 上限、生成长度、贪婪解码和模板。跨家族可以使用原生预处理，但必须披露实际视觉 token 成本。
- 大模型 4-bit/8-bit 只作为量化敏感性实验，不将量化 32B 与非量化 7B 混成规模主证据。[Transformers 官方量化文档](https://huggingface.co/docs/transformers/quantization/bitsandbytes)
- 预检同时覆盖四条轴、长输出、极端宽高比和旧数值失败样本；检查非有限 logits、OOM、截断及处理器输入映射。

## 6. C 阶段改进：预注册统计终点与 gate

### 6.1 分开三个研究问题

| 问题 | 主要证据 | 不足以支持它的证据 |
|---|---|---|
| H1：存在量尺依赖 | 同一家族内，定义有效且覆盖足够的量尺产生严格轴排序分歧，超过配对噪声 | 平局造成的正 F、失效定位接口、仅不同家族间的差异 |
| H2：floor 是主要机制 | 坐标冻结和同质 floor 对照在相同题集/抽样下有可重复影响 | 仅给出代数上可能翻转的植入例子 |
| H3：选轴影响训练预算后果 | 独立确认集上，多种子训练臂差值和跨轴代价 | 单 seed 原始增益最高、C 在其他家族上的 go |

H1、H2、H3 分别判定。H2 不成立不等于全部研究无价值，但必须如实改写机制结论；H1 成立也不能自动推出 H3 成立。

### 6.2 统计方法

- 模型、退化答题器和训练臂共用相同的配对重采样索引。
- 主推断以原图/原始来源簇为单位，在数据子集/学科内分层；一致性的五改写不可独立重采样。同图跨轴时保留跨轴关联。
- C 同时计算 `F_scale-F_noise` 的配对分布及区间，而不仅并列两个边际区间；在同一外层图像簇重采样中重估两者，并冻结噪声过程及内层重复规则，不能把已有两个独立 Bootstrap 数组逐项相减；保留旧 gate 以便对照。
- C 延续 1,000 次旧协议复现；新确认分析预注册更充分的重采样次数，并报告 Monte Carlo 稳定性，不能反复计算到“显著”为止。
- D 主比较直接计算 A1-A2、A1-U、A1-N 的差值区间。主比较族使用预先声明的多重比较校正；各轴结果作为分量另报。
- 对多种子结果，按 seed 与原图簇做交叉配对重采样：每次抽取 seed，再让所有 seed/臂共用同一套评测簇权重；保留同图跨轴关联，不在各 seed 内独立抽不同题集。同时展示逐 seed 结果和普通 seed 均值/离散程度。只有 3 个 seed 时不夸大区间精度。
- 类数、rho 网格点和改写版本不作为独立重复数。

统计检验应依据配对结构与终点类型选择，而不是看到结果后挑检验。[Dror 等，ACL 2018](https://aclanthology.org/P18-1128/)

### 6.3 明确停止与继续条件

先保留原协议的结果，再按冻结的新协议分别判定：

1. **测量有效性门槛**：坐标契约、数值和最小覆盖通过；失败时不能将四轴分析完整性等同于四轴能力都被有效测量。
2. **审计存在性门槛**：严格排序分歧超过预注册的噪声基线。多家族主张需要独立家族重复，不能用一个家族的 go 代替全部家族。
3. **目标家族门槛**：对实际训练家族单独报告证据。如果合理量尺都选同一轴，后续只能检验任务训练收益，不能声称验证“换尺导致预算选择不同”。
4. **预算机制门槛**：确认所比较的规则确实选择不同轴；若两种规则选同一轴，应合并重复训练臂，不通过换阈值制造分歧。

新 gate 按预注册的配对差值区间、严格反转指标与最小效应门槛判定；差值区间跨零或未达到预注册的证据门槛时记为 indeterminate。两个边际区间是否重叠只用于图示和旧 gate 对照，不能代替配对差值检验。全部合理尺稳定且没有严格反转时接受负结果，不追加模型直到出现希望的结论。

## 7. D 阶段改进：公平训练、多种子与更强教师

### 7.1 两层训练配置

| 配置 | 学生 | 教师 | 用途 |
|---|---|---|---|
| 复现桥接 | Qwen2.5-VL 3B | Qwen2.5-VL 7B | 验证旧结果在修正协议、独立确认和多 seed 下是否保持 |
| 推荐大模型主线 | Qwen2.5-VL 7B | Qwen2.5-VL 32B | 检验学生与教师能力提高后，量尺/预算后果是否仍存在 |
| 第二家族增强 | InternVL3 8B | InternVL3 14B | 在另一家族复现训练后果，前提是目标家族 gate 和输入/蒸馏接口验收通过 |

3B+7B 与 7B+32B 同时改变了学生和教师，不能把差异单独归因于其中一个。若要区分教师增强效应，增加固定 3B 学生、7B/32B 教师的控制；不必一开始就运行完整学生×教师全因子矩阵。

InternVL 的原生 chat 输入、assistant token 定位和 logits 缓存接口需要单独实现，不能假定现有仅支持 Qwen 的训练接口直接可用。

### 7.2 训练臂与重复次数

- 保留 A1、A2、U、N，A1/A2 由审计集一次选定，不能按每个确认结果重新选择。
- 所有臂使用同一学生初始权重、LoRA 结构、公共超参、有效 batch 和图像预算；同一 seed 配对初始化与采样规则。
- 建议每个配置 5 个新 seed，最低 3 个；例如预先冻结一组 seed 后全部执行。旧单 seed 作为探索基线，不冒充新增确认性重复。
- 原步数主线延续 `r=16, alpha=32, lr=1e-4, 1,000` 次实际更新；若 7B 需要调公共超参，只能在开发集使用统一、有限的搜索预算，所有臂采用同一结果。
- 3 个有效训练臂×5 seed = 15 次训练/配置；N 不需要重复无意义的参数更新或相同贪婪推理。桥接与大模型两个配置合计最多 30 次有效训练，均受前述 gate 约束。

### 7.3 改善“等步数”比较

原训练池的一致性轴只有 349 个原题、1,745 个改写样本，其他轴各 600 条。直接按行采样会使原题多样性、重复率和曝光量不同。

新采样先选原题，再按固定规则选择改写。预先统计每轴唯一原题、图像、监督 token 和视觉 token。

安排两种清楚分开的比较：

1. **原协议步数匹配**：相同 1,000 次更新，任务分配差异作为处理因素；完整披露每轴曝光量。
2. **预算公平敏感性**：匹配总原题池规模、重复采样规则及监督 token 预算，并报告允许误差；例如 A1/A2 各 600 个原题，U 每轴 150 个原题，总数同为 600。不要在这一控制中消除本来要研究的“预算投向不同轴”本身。

补充报告实际 GPU 小时或估算 FLOPs。相同步数不等于相同计算量；不能同时声称步数、token、唯一图片数和 FLOPs 全部相等，除非逐项验证。

### 7.4 教师质量与蒸馏机制控制

- 在独立训练校准集上检查教师正确率、解析率、答案长度及截断；更大的教师不保证在每条代理任务上都更好。
- 保持教师缓存与学生训练分开，卸载教师后再训练学生。
- 先验证 tokenizer、词表 ID、特殊 token 和 assistant 边界。只有完全对齐才能直接做 top-50 logits 蒸馏；不对齐时采用预注册的答案序列蒸馏或明确的映射方法。
- 用少量预注册 seed 做 `CE-only` 与 `CE+KD` 对照；必要时增加真实训练标签 CE，区分教师目标质量、训练轴选择和软标签损失的作用。
- 教师错误过滤只能根据训练/开发数据预先定义，并对所有训练臂一致应用。

### 7.5 主效应、负迁移和实际意义

主表同时给出 `G_floor`、`G_raw`、四轴分量及训练臂差值的区间；预先声明最小实际意义阈值，基于应用价值和开发集功效模拟确定，不能照当前 0.317 的差值反推。

保留 U 定位下降这一类负迁移，增加“最差轴变化”和跨轴代价表。若 A1-A2 的区间跨零，结论写为未证明优于 A2；若多数 seed 方向相反或平均收益接近零，则不能以一个最好 seed 支持方法有效。

## 9. 硬件、显存和时间预算

### 9.1 已测显存作为工程参照

现有 PyTorch 分配峰值：Qwen 3B 推理约 8.78 GiB、7B 约 17.29 GiB；3B 三个 LoRA 训练臂约 9.01-9.14 GiB。它们不是 nvidia-smi 整卡占用，不能直接按参数比外推训练显存。[完整测量](https://github.com/Jerry-114514/Jerry-vibe-coding/blob/codex/arp-autodl/docs/results/vram-20261016/README.md)

### 9.2 推荐硬件

| 硬件 | 推荐用途 | 条件 |
|---|---|---|
| 现有 24GB 4090 | CPU 补分析、3B/7B 旧配置桥接及小规模预检 | 新精度和输入预算仍需实测 |
| 单 48GB | 7B/8B/14B BF16 推理、7B LoRA 预检 | 固定视觉预算、batch=1、梯度检查点 |
| 单 80GB | Qwen 32B 教师离线缓存，再串行训练 7B 学生 | 不让教师和学生同时常驻；留出视觉和 KV 余量 |
| 2×80GB | InternVL3 38B、LLaVA 72B 的优先候选 | 模型分片、受控上下文、必须先通过预检 |
| 4×80GB | 72B 更高视觉预算或长上下文的增强实验 | 根据预检决定，不默认全部租用 |

按标称参数及每参数 2 字节粗算的纯权重下界：14B 约 26.1 GiB，32B 约 59.6 GiB，38B 约 70.8 GiB，72B 约 134.1 GiB。实际总参数、视觉塔、KV、激活、临时工作区、优化器均另计；这些数值不是运行显存承诺。

单 48GB 无法让名义 32B 的完整 16 位权重全部驻留。建议先用 80GB 完成 32B 主线，而不是为省显存把量化引入规模主分析。

### 9.3 用预检估算工时，不编造大模型速度

先测每个新模型分轴约 100 条推理及每种训练配置 100 个有效更新，再按实际 token、图像 patch 和输出长度外推。

```text
推理时间估计 = Σ_轴 (该轴题量 × 该轴预检每题时间)
训练时间估计 = 配置数 × 有效臂数 × seed数 × 每步时间 × 1000
最终评测时间 = 配置数 × 有效臂数 × seed数 × 每次完整确认评测时间
```

若确认集四轴各 1,200 个原题，其中一致性每题 5 改写，则每个模型/适配器需 9,600 条提示；一个配置 3 臂×5 seed，仅训练后评测就有 144,000 条提示，不含基础审计与桥接。

排期先留 P0 与数据校准约 1-2 个工作日作为人工安排，再根据大模型预检锁定 GPU 小时。卡价、租赁可用性和总费用另按执行时实价计算，不把当前 3B 速度当作 32B/72B 的保证。

## 10. 版本、存储、显存记录和交付改进

为避免与现有后端版本混淆，将下一轮研究协议命名为 `protocol-v2`，并单独记录 inference backend revision。每次变更同时记录数据、解析器、数值、模型、量尺与训练协议哈希。

建议目录：

```text
runs/protocol-v2/
  preregistration/       # 假设、终点、seed、阈值、停止规则
  manifests/             # train / calibration / audit / confirm
  calibration/           # 坐标契约、精度桥接、错误盲审
  ledger/                # 全部基础模型逐题输出
  analysis/              # 120设置、结构/经验商集、严格反转与并列
  teacher-cache/         # 每教师和训练清单独立缓存
  arms/<config>/<arm>/<seed>/
  post/<config>/<arm>/<seed>/
  memory/                # 全阶段采样、进程级和框架级指标
  tables/                # 终点、差值、负迁移、成本
  verification/          # 公式一致性、覆盖、哈希、实际更新、上传验收
```

新增每阶段记录：PyTorch allocated/reserved 峰值、nvidia-smi 总占用及进程占用、采样间隔、GPU 型号、dtype、图像/文本 token、耗时与成本。采样峰值和框架峰值分别报告；C 虽主要是 CPU 分析，也记录整卡背景占用，历史缺测仍标记缺测。

数据和训练继续在 AutoDL 运行。代码、协议和小型报告进入 Git；大数据、教师缓存、LoRA、恢复状态与原始账本放 GitHub Release，按阶段上传并验证服务端 SHA256。基础权重记录官方 revision/文件 SHA，不重复塞入普通 Git。

每阶段最终验收除“脚本没有报错”外，还要检查公式契约、分层覆盖、共同定义域、缓存对齐、真实更新次数、完整确认评测、图表来源和上传清单。发现定义改变时，旧运行仍保留为历史结果。

## 11. 论文结果应如何组织

建议将论文主张拆成“测量审计”与“预算后果”两层，允许两层得到不同强度的结论。

| 证据情况 | 可以写的结论 | 不应写的结论 |
|---|---|---|
| 修正后多个家族仍严格翻转 | 已发布模型的轴选择对合理量尺敏感 | 所有现象都由参数大小造成 |
| floor 影响仍弱、同质对照不改变选臂 | 主要敏感性可能来自其他坐标或交互 | 已证明 floor 是主因 |
| A1-A2 差值区间跨零 | 未证明所选策略优于 runner-up | 只因 A1 点估计最高就宣称胜出 |
| 换尺后训练臂排名改变 | 方法优劣评价本身对效用定义敏感 | 量尺类数就是独立重复数 |
| 仅 Qwen 完成预算复现 | 多家族审计、Qwen 家族预算实证 | 已证明预算策略跨所有家族有效 |
| 原生坐标协议改善后现象消失 | 旧现象主要受接口约定影响 | 旧低分代表模型没有该能力 |

优先生成：公式差异表、测量有效性表、严格反转/平局/guard 表、同质 floor 对照、各 seed 训练臂差值、逐轴负迁移、跨家族复现与 GPU 成本表。

## 12. 可直接执行的顺序

1. 冻结现有 v1 成果、代码 commit 和数据哈希，保存本方案版本。
2. 完成 P0 公式与估计量审查，建立有解析答案的测试例，重算已有 C/D。
3. 输出旧新结论对照，决定哪些原主张仍可保留，哪些应降级。
4. 完成定位盲审与原生格式校准，冻结 BF16/旧精度桥接。
5. 准备相互分离的新训练、开发、审计和确认清单；先做功效与资源预检。
6. 预注册主终点、seed、比较族、停止规则、共同商集与量尺范围。
7. 执行 Qwen 三点及 Intern 三点基础审计；按目标家族 gate 决定是否进入预算实验。
8. 优先完成 3B/7B 多 seed 桥接，再执行 7B/32B 主线；若预算受限可缩减增强项，但不可只保留最有利 seed。
9. 冻结确认集后统一跑全部训练臂，计算配对区间和负迁移，按阶段备份。
10. 达到预定证据要求后，再决定是否运行第二家族训练、38B/72B 与蒸馏机制消融。
