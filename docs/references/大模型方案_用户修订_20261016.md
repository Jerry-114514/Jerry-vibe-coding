## 1. P0：定义对齐与已有数据补分析（纯 CPU，0 成本）

P0 完全不涉及新模型推理，在本地用已有原始账本重算。自审文档 §3 的要求原样执行，此处不重复，仅补充执行细节。

### 1.1 P0-1：公式/代码逐式核对

**输入**：研究标准卡 `idea.std.zh.pdf` 的式(1)–(5)、`analyze_rulers.py`、`export_results.py`

**执行步骤**：

1. 逐式列出标准卡公式、代码实现、差异点，输出 `formula_audit.md`
2. 重点核查：
   - 相对掉分分母：标准卡用大模型分母 `(x_L - x_s) / x_L`，代码用小模型分母 `(x_L - x_s) / x_s`
   - floor 校正后的相对差：`(x_L - x_s) / (x_L - c_a)` vs 代码实现
   - 训练净增益 G_net：标准卡式(5) 的 `G_floor = Σ_a [(x_post,a - x_pre,a) / (1 - c_a)]` vs `export_results.py` 的 `ruler_vector` 调用
3. 建立单元测试：零分母、sub-floor、负变化、headroom 分母符号
4. 按修正公式重算 C（量尺分析）和 D（训练增益），保留旧结果作 v1 对照

**产物**：`formula_audit.md`、`analysis_v1_vs_v2.csv`、单元测试脚本

**工时**：约 4–6 小时 CPU 计算 + 2 小时人工审查

### 1.2 P0-2：平局与严格反转分解

**核心问题**：Qwen F_scale=0.083 可能全部来自 headroom 退化的定义性平局，而非真实排序反转。

**执行步骤**：

1. 对每个等价类，输出四轴的 headroom 归一化后值向量
2. 分类为：唯一最大轴不同（严格反转）、全平局（headroom=1 退化）、部分并列、无有效轴
3. Qwen 9 个类逐一核实：哪些有 `u_a = x_L` 导致 headroom=1 全平局
4. 固定并列阈值主值 ε=0.01，同时报告 ε∈{0, 0.005, 0.01, 0.02} 的敏感性
5. 输出每个类的分母诊断（分母值、符号、是否触发护栏）

**产物**：`tie_and_guard_report.csv`、`denominator_diagnostics.csv`

### 1.3 P0-3：全 120 设置与共同题集

**执行步骤**：

1. 枚举全部 120 个原始设置（不仅用 B 上折叠后的 9/54/10 类代表）
2. 对所有训练臂使用同一冻结题目集：所有臂的共同有效原题/原图交集
3. 重算训练增益：120 设置 × 4 臂，完整增益表
4. 报告交集大小、分层分布、被排除题目特征

**产物**：`arm_common_support.csv`、120 设置完整增益表

### 1.4 P0-4：定位盲审

**背景**：InternVL 解析失败率 92.8%–99.9%，LLaVA 7B 可解析但定位分数为 0。

**执行步骤**：

1. 每模型抽取 ~200 条定位原始输出
2. 人工分类：格式错误、坐标单位错误（归一化 vs 像素 vs 千分比）、图像缩放映射错误、有效但定位错误、截断
3. 对 InternVL 家族：确认其原生输出格式（InternVL3 使用 `<ref>...<box>[[x1,y1,x2,y2]]</box></ref>` 格式，坐标为千分比）
4. 冻结各家族的坐标契约：Qwen 用像素坐标，InternVL 用千分比，LLaVA 用归一化坐标
5. 建立原生输出协议：统一映射到原图坐标，转换规则预先声明

**产物**：`grounding_error_taxonomy.csv`、冻结的坐标契约文档

**注意**：这一步需要少量 GPU（加载模型生成样本），可在现有 4090 上完成。

| 模型 | 位置 | 定价 | 说明 |
|---|---|---|---|

| Qwen2.5-VL-7B | 本地 4090 | ¥0 | 已有 v1 结果 |

| 模型 | 总参/激活 | 位置 | 定价（$/百万token） | 用途 |
|---|---|---|---|---|
| **Qwen3.5-122B-A10B** | 122B/10B | DashScope `qwen3.5-122b-a10b` 或 OpenRouter | ~$0.26/$2.08 | **主线蒸馏教师** |

**关键设计原则：审计阶梯与蒸馏教师分离**

- **审计阶梯**用 Qwen2.5-VL 同系列（3B → 7B → plus → max），保持 Dense 架构一致性，避免 MoE vs Dense 混杂
- **蒸馏教师**用 Qwen3.5-122B-A10B，跨代但不混入阶梯。教师只提供训练目标文本，不参与量尺分析
- Qwen3.5 可作为**独立标注的跨代检查点**参与敏感性分析，但必须与 Qwen2.5-VL 阶梯分表报告

**Qwen3.5-122B-A10B 做教师的优势**：
1. 总参 122B，教师质量远超 qwen-vl-plus（~32B），蒸馏信号更强
2. 激活仅 10B（MoE），API 推理快、成本极低（16,900 条审计约 ¥45，3,545 条教师缓存约 ¥10）
3. 原生多模态（官方 "Towards Native Multimodal Agents"），四轴评测均可用
4. 序列级蒸馏不需要 tokenizer 对齐，跨代组合完全可行

**Qwen3.5 已知风险**：
1. 定位格式使用千分比坐标 `<box>(x1,y1,x2,y2)</box>`，与 Qwen2.5-VL 像素坐标不同，解析器需适配
2. sglang 报告 ~90px 坐标偏移 bug（[sglang#36762](https://github.com/sgl-project/sglang/issues/36762)），须在校准集验证
3. DashScope 不支持 logprobs — 只能做序列级蒸馏
4. 397B 可能需走 OpenRouter（DashScope 未确认直接 model ID）

**不推荐**：
- Qwen3.5-35B-A3B / Qwen3.6-35B-A3B：激活仅 3B，对 7B 学生无能力优势；Qwen3.6 定位输出不稳定

**DashScope 审计阶梯的版本控制**：
- 使用 `-latest` 快照版本（如 `qwen-vl-plus-2026XXXX`），冻结 API 版本
- 论文措辞为"官方商业化检查点阶梯"，不声称精确等于特定参数量

### 4.5 精度桥接

自审文档 §5.3 要求：

- API 推理与本地推理的精度可能不同（API 内部可能用 INT8/FP8 加速）

## 5. P1-4：7B 学生 + 122B 教师训练（核心实验）

### 5.1 蒸馏方案选择

**关键约束**：DashScope API **不返回 logprobs**，无法做 top-k logits KL 蒸馏。

有两条路径：

#### 方案 A：序列级蒸馏（推荐，低成本）

```
教师：Qwen3.5-122B-A10B API（DashScope 或 OpenRouter）
蒸馏信号：教师生成的完整回答文本
损失函数：CE loss（学生拟合教师文本）
不需要 logits，不需要 tokenizer 对齐
```

**理论支撑**：
- Kim & Rush (2016) "Sequence-Level Knowledge Distillation" 是序列级蒸馏的经典方法
- LLaVA-KD (Cai et al., ICCV 2025) 证明在 MLLM 蒸馏中，response-based KD 单独就有显著收益，与 word-level KD 的差距约 1–3%
- arXiv:2404.14827 系统对比表明，教师-学生能力差距较大时，sentence-level KD 甚至可能更好
- Agarwal et al. (GKD, ICLR 2024) 的 on-policy 框架支持无 logits 的 "On-policy + SeqKD" 变体
- **教师升级**：Qwen3.5-122B 总参 122B 远超之前考虑的 ~32B 级，教师回答质量大幅提升，序列级蒸馏的信号更强

**协议变更**：
- 原协议：`loss = 0.5 × CE(student, label) + 0.5 × KL(student, teacher_logits)`
- 新协议：`loss = 0.5 × CE(student, label) + 0.5 × CE(student, teacher_response)`
- 这个变更需要在论文中明确说明，并做蒸馏机制消融（见 §5.5）

#### 方案 B：自部署 vLLM 获取 logits（高成本，可选增强）

```
教师：AutoDL A100-80GB + vLLM 部署 Qwen2.5-VL-32B BF16
蒸馏信号：top-50 logits
损失函数：top-50 KL + tail-bucket（与 v1 完全一致）
注意：此方案用 Qwen2.5-VL-32B（同系列 Dense），不用 Qwen3.5
```

**已知风险**：
- vLLM 的 VL 模型 logprobs 存在多个 bug（[#16107](https://github.com/vllm-project/vllm/issues/16107)、[#12699](https://github.com/vllm-project/vllm/issues/12699)、[#19177](https://github.com/vllm-project/vllm/issues/19177)）
- Qwen2.5-VL-32B BF16 权重 ~60GB，单 A100-80GB 紧张（含 KV cache 约 73GB）
- 成本：租 A100 约 ¥6.68/h，缓存 3,545 条 logits 估计 ~10h = **¥67**；但前期调试/验证可能额外花 10–20h

**建议**：
- **主线用方案 A（序列级蒸馏）**，成本低、实现简单、有文献支撑
- 方案 B 作为**预注册的蒸馏机制消融实验**（自审文档 §7.4 的 CE-only vs CE+KD 对照），若预算允许再执行
- 如果方案 B 证明 KL 蒸馏显著优于序列级蒸馏，再考虑将其提升为主线

### 5.2 序列级蒸馏的教师缓存

```python
# 教师回答缓存流程
for item in training_pool:  # 3,545 条
    response = dashscope_api.generate(
        model="qwen3.5-122b-a10b",  # Qwen3.5 MoE 教师
        image=item.image,
        prompt=item.prompt,
        max_tokens=128,
        temperature=0  # 贪婪解码
    )
    cache[item.id] = {
        "teacher_response": response.text,
        "teacher_tokens": tokenizer.encode(response.text),  # 用学生(Qwen2.5-VL-7B)的 tokenizer
        "finish_reason": response.finish_reason
    }

# 缓存后离线训练，教师完全不占显存
```

**缓存成本**：3,545 条 × ~800 token/条 ≈ 284 万 token → DashScope plus 约 **¥5–10**

### 5.5 蒸馏机制消融（自审文档 §7.4）

## 6. 统计分析与 Gate（自审文档 §6 执行）

### 6.1 三个研究假设独立检验

| 假设 | 主要证据 | 判定方式 |
|---|---|---|
| H1：存在量尺依赖 | 严格排序分歧超过噪声基线 | F_scale - F_noise 的配对差值 CI 不含 0 |
| H2：floor 是主要机制 | 同质 floor 对照改变选臂/F_scale | 冻结坐标 + 同质对照的 F 变化 |
| H3：选轴影响训练预算 | 多 seed 训练臂差值 | A1-A2 的配对 bootstrap CI 不含 0 |

### 6.2 统计方法

- 配对重采样：模型、退化答题器和训练臂共用相同索引
- 以原图/来源簇为单位，五改写不可独立重采样
- D 主比较：A1-A2、A1-U、A1-N 差值区间，Bonferroni 或 Holm 校正
- 多 seed：按 seed × 原图簇交叉配对重采样
- 3 个 seed 时不夸大区间精度；5 个 seed 时报告逐 seed 结果 + 均值 ± 标准差

### 6.3 停止规则

1. P0 完成后若公式修正导致旧 gate 翻转 → 直接报告，不追加模型
2. P1-3 审计若所有合理量尺选同一轴 → 后续只检验训练收益，不声称"换尺导致不同"
3. A1-A2 区间跨零 → 写"未证明"，不追加 seed

## 9. 关键风险与应对

### 9.1 DashScope 模型版本不可控

**风险**：`qwen-vl-plus` 底层模型可能在实验期间更新，导致前后结果不可比。

**应对**：
- 使用 `-latest` 快照版本（如 `qwen-vl-plus-2026XXXX`），冻结 API 版本
- 审计推理集中在 1–2 天内跑完，减少版本切换风险
- 论文中标注 API 调用日期和版本

### 9.2 序列级蒸馏 vs KL 蒸馏的性能差异

**风险**：序列级蒸馏可能导致训练效果弱于 v1 的 KL 蒸馏，影响 H3 的证据强度。

**缓解因素**：Qwen3.5-122B 教师（总参 122B）远强于 v1 的 Qwen2.5-VL-7B 教师，更高质量的教师回答可能补偿序列级蒸馏的信息损失。

**应对**：
- 桥接实验（P1-2）用原协议 KL 蒸馏（Qwen2.5-VL-7B 教师），确保 v1 结果可复现
- 主线实验（P1-4）用序列级蒸馏（Qwen3.5-122B 教师），作为独立配置
- 论文框架允许两层结论不同强度
- 若桥接结果与 v1 一致但主线弱 → "旧配置可复现，新配置下效应减弱，可能与蒸馏机制有关"

### 9.3 7B 学生在 4090 上 OOM

**风险**：7B + LoRA + gradient checkpointing 约 18–20GB，4090 的 24GB 可能不够。

**应对**：
1. 先跑 100 步预检，确认峰值显存
2. 若 OOM → gradient_accumulation=2，等效 batch 不变
3. 若仍 OOM → 仅对语言层加 LoRA，不加视觉层
4. 最后手段：学生降为 3B，教师用 32B API（仍是配置升级）

### 9.4 InternVL3-14B 无 API 且自部署昂贵

**风险**：SiliconFlow 可能已下架 InternVL3-14B，自部署 A100 需 ¥380。

**应对**：
- 优先级：SiliconFlow > OpenRouter > AutoDL lmdeploy > 本地 4090 AWQ（仅敏感性）
- 如果全部不可行 → InternVL 家族暂用 1B/2B/8B 三点（已有），在论文中说明

### 9.5 API 解析结果与本地不一致

**风险**：API 的生成格式可能与本地推理不同（如更长、更结构化的回答），导致解析失败率不同。

**应对**：
- 精度桥接实验（§4.5）会检测这种差异
- 使用与本地完全相同的 prompt 模板和 system prompt
- 设置 `temperature=0`，强制贪婪解码
- 如果解析失败率差异 > 5% → 在 API 端调整 prompt 直到对齐
